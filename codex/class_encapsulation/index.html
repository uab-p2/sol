    Encapsulamiento¶

    Una clase ofrece una cara pública y mantiene una cara restringida. Quien diseña la clase decide qué partes son accesibles desde fuera (public:) y cuáles quedan reservadas a la propia clase (protected:/private:).

    Por ejemplo, un ascensor puede ofrecernos un botón que pulsar, pero no nos deja manipular el motor y mover la caja directamente:

    /// A simple elevator serving floors from 1 to a fixed top floor.
class Elevator {
public:
    /// Create an elevator serving floors 1 to top_floor.
    /// @param top_floor highest floor served (must be >= 1).
    Elevator(int top_floor);

    /// Request the elevator to go to the given floor. Ignored if
    /// floor is not between 1 and the top floor.
    /// @param floor destination floor.
    void push_button(int floor);

    /// @return the floor where the elevator currently is.
    int get_current_floor() const;

private:
    /// Move the elevator box straight to the given floor, without
    /// any validation. Only push_button() may call this, after
    /// checking that the floor is valid.
    /// @param floor destination floor.
    void move_box(int floor);

    /// Current floor. Starts at the ground floor (1).
    int m_current_floor = 1;

    /// Highest floor served by this elevator.
    int m_top_floor;
};

    public:, protected: y private:¶

    Las palabras clave public:, protected: y private: controlan el acceso a cada parte de la clase.

    Estas palabras clave marcan el comienzo de una región, con vigencia hasta la siguiente o hasta el final de la clase.

    Atributos, getters y setters¶

    Atributos¶

    En este proyecto, declaramos todos los atributos protected: o private:.

    Sólo el código de nuestra clase tiene la responsabilidad de mantener estados válidos; el resto de clases no puede modificar este estado directamente.

    Getters¶

    Para cada atributo podemos crear un getter, un método público que devuelve el valor de ese atributo.

    • Su nombre comienza por get_ (o is_ si el atributo es bool), seguido del nombre del atributo sin m_.

    • Retorna el tipo de dato del atributo.

      • Si el atributo es de un tipo básico, el retorno es de ese mismo tipo.

      • Si el tipo de un atributo es una clase, el retorno puede ser una copia o una referencia al propio atributo.

    • No acepta argumentos.

    • Es un método const; no altera el estado del objeto durante la consulta.

    Setter¶

    Independientemente del getter, podemos crear setters para nuestros atributos.

    • Su nombre comienza por set_, seguido del nombre del atributo sin m_.
    • No retorna nada (void).

    • Toma un argumento, cuyo tipo depende del del atributo.

      • Si el atributo es de un tipo básico, el argumento del setter es ese mismo tipo.

      • Si el tipo de un atributo es una clase, el argumento del setter es una referencia const.

    • No es un método const.

    • Puede validar, modificar o rechazar el cambio para preservar la lógica (ver set_chalks debajo).

    Herencia

    La herencia es...

    • reutilización de atributos/métodos en la clase base
    • Constructors aren't inherited automatically — Derived must call each base's constructor explicitly
    • referencias de la clase base para manejo de objetos de las clases derivadas
    • : public A vs : A

    • métodos virtuales y polimorfismo -> actually split polymorphism to its own section

    • access to parent methods A::f() other.Z::g()

    multiple inheritance: - Each base class access specifier (public, protected, private) controls how that base's members are exposed in Derived. - If two bases have members with the same name, you must disambiguate: d.Base1::foo(); in its init list if they need arguments:

    Atributos, getters y setters

    Atributos¶

    En este proyecto, declaramos todos los atributos protected: o private:.

    Sólo el código de nuestra clase tiene la responsabilidad de mantener estados válidos; el resto de clases no puede modificar este estado directamente.

    Getters¶

    Para cada atributo podemos crear un getter, un método público que devuelve el valor de ese atributo.

    • Su nombre comienza por get_ (o is_ si el atributo es bool), seguido del nombre del atributo sin m_.

    • Retorna el tipo de dato del atributo.

      • Si el atributo es de un tipo básico, el retorno es de ese mismo tipo.

      • Si el tipo de un atributo es una clase, el retorno puede ser una copia o una referencia al propio atributo.

    • No acepta argumentos.

    • Es un método const; no altera el estado del objeto durante la consulta.

    Setter¶

    Independientemente del getter, podemos crear setters para nuestros atributos.

    • Su nombre comienza por set_, seguido del nombre del atributo sin m_.
    • No retorna nada (void).

    • Toma un argumento, cuyo tipo depende del del atributo.

      • Si el atributo es de un tipo básico, el argumento del setter es ese mismo tipo.

      • Si el tipo de un atributo es una clase, el argumento del setter es una referencia const.

    • No es un método const.

    • Puede validar, modificar o rechazar el cambio para preservar la lógica (ver set_chalks debajo).
