    Autocorrección con gradescope¶

    El proyecto SOL ofrece un sistema de autocorrección con gradescope. Te explicamos qué esperar de este sistema y cómo usarlo.

    Cuándo subir tu solución¶

    Primero trabaja tu solución localmente. Compila tanto main como test e itera hasta que tu solución esté lista para la entrega definitiva.

    Sólo entonces entrega (dentro de las fechas de entrega mostradas por gradescope).

    Danger

    Escribir todo el código sin probarlo y enviarlo directamente a gradescope ralentiza enormemente el trabajo.

    Cómo subir tu solución¶

    En el Dashboard de gradescope, haz click en la entrega titulada igual que el quest. Arrastra todos los ficheros *.h y *.cpp de la carpeta del quest quest/<nombre_del_quest> a gradescope y pulsa Upload.

    Cómo interpretar la salida¶

    make¶

    Resultado de la compilación. Si no funciona, la autocorrección concluye con un 0.

    Tiene 3 secciones importantes:

    • build status: determina si la compilación ha tenido éxito o no se han podido crear los ejecutables. Un código de estado 0 significa éxito.
    • stdout: salida normal del compilador. En caso de éxito contendrá [ 50%] Built target main y [100%] Built target test, entre otras cosas.
    • stderr: mensajes de warning y de error durante la compilación. Idealmente este apartado debería estar vacío. Si no lo está, revisa los mensajes y corrige los errores.

    Tests funcionales¶

    Para cada uno de los tests funcionales, verás test result: failed o test result: passed y una un valor numérico.

    El campo Total points contiene la puntuación final de los tests funcionales calculada únicamente en base a estos tests.
