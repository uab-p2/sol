    Orden¶

    En este proyecto usamos el siguiente orden de declaración e implementación de miembros en los ficheros .h y .cpp:

    1. Parte pública:

      1. Constructores.
      2. Destructores.
      3. Métodos públicos interfaz principal.
      4. Getters y setters.
      5. Operadores sobrecargados.
      6. Constantes públicas.

    2. Parte protegida/privada:

      1. Métodos protegidos/privados.
      2. Constantes protegidas/privadas.
      3. Atributos protegidos/privados.

    Atributos, getters y setters

    Atributos¶

    En este proyecto, declaramos todos los atributos protected: o private:.

    Sólo el código de nuestra clase tiene la responsabilidad de mantener estados válidos; el resto de clases no puede modificar este estado directamente.

    Getters¶

    Para cada atributo podemos crear un getter, un método público que devuelve el valor de ese atributo.

    • Su nombre comienza por get_ (o is_ si el atributo es bool), seguido del nombre del atributo sin m_.

    • Retorna el tipo de dato del atributo.

      • Si el atributo es de un tipo básico, el retorno es de ese mismo tipo.

      • Si el tipo de un atributo es una clase, el retorno puede ser una copia o una referencia al propio atributo.

    • No acepta argumentos.

    • Es un método const; no altera el estado del objeto durante la consulta.

    Setter¶

    Independientemente del getter, podemos crear setters para nuestros atributos.

    • Su nombre comienza por set_, seguido del nombre del atributo sin m_.
    • No retorna nada (void).

    Atributos, getters y setters

    Atributos¶

    En este proyecto, declaramos todos los atributos protected: o private:.

    Sólo el código de nuestra clase tiene la responsabilidad de mantener estados válidos; el resto de clases no puede modificar este estado directamente.

    Getters¶

    Para cada atributo podemos crear un getter, un método público que devuelve el valor de ese atributo.

    • Su nombre comienza por get_ (o is_ si el atributo es bool), seguido del nombre del atributo sin m_.

    • Retorna el tipo de dato del atributo.

      • Si el atributo es de un tipo básico, el retorno es de ese mismo tipo.

      • Si el tipo de un atributo es una clase, el retorno puede ser una copia o una referencia al propio atributo.

    • No acepta argumentos.

    • Es un método const; no altera el estado del objeto durante la consulta.

    Setter¶

    Independientemente del getter, podemos crear setters para nuestros atributos.

    • Su nombre comienza por set_, seguido del nombre del atributo sin m_.
    • No retorna nada (void).

    • Toma un argumento, cuyo tipo depende del del atributo.

      • Si el atributo es de un tipo básico, el argumento del setter es ese mismo tipo.

      • Si el tipo de un atributo es una clase, el argumento del setter es una referencia const.

    • No es un método const.

    • Puede validar, modificar o rechazar el cambio para preservar la lógica (ver set_chalks debajo).
