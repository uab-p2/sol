    Clases: ¿por qué?¶

    ¿Para qué sirven las clases y la programación orientada a objetos? Damos algunas respuestas posibles:

    Ideas cercanas¶

    Clases y objetos nos permiten pensar y expresar nuestras ideas en términos un poco más humanos.

    Así, podemos hablar de puerta con Door door; sin tener que pensar en todos los detalles (ángulo, cerrojo, etc.).

    classDiagram
  class Door {
    bool open()
    void close()
    void lock(bool)
    float angle
    bool locked
  }

    Estados coherentes¶

    La programación orientada a objetos busca mantener un estado definido y válido en todo momento con ayuda de los principios de encapsulamiento y RAII.

    Por ejemplo, podríamos diseñar una puerta que sólo admita tres estados: abierta, cerrada y bloqueada, como muestra el diagrama de estado siguiente. 

    stateDiagram-v2
  [*] --> Closed
  Closed --> Locked: lock(true)
  Locked --> Closed: lock(false)
  Closed --> Open: open(), !locked
  Open --> Closed: close()

    Los objetos nos ayudan a evitar estados intermedios "absurdos" (como un cerrojo echado con la puerta abierta), o transiciones inválidas (como abrir una puerta bloqueada sin desbloquearla con la llave antes).

    Reutilización y compartición de código¶

    Una clase se define una única vez y se puede instanciar (crear objetos) tantas veces como haga falta. Por ejemplo, podríamos usar la misma clase Timer en un evento deportivo, o para el temporizador de un horno.

    La composición, la herencia y las plantillas son los tres mecanismos principales para reutilizar código.

    La división en ficheros .h y .cpp, la documentación y la señalización clara del interfaz público facilitan el uso de código creado por otras personas (o máquinas).

    #pragma once

/// A simple mission timer that accumulates elapsed seconds.
class Timer {
public:
    /// Create a new timer with zero elapsed time.
    Timer();

    /// Advance the timer by the given number of seconds.
    void tick(double seconds);

    /// Reset the elapsed time back to zero.
    void reset();

    /// Complete a lap and return its duration. Then reset the timer.
    /// @return the lap duration.
    double lap();

private:
    /// Accumulated seconds since the last reset.
    double m_elapsed;
};

    #include "timer.h"

Timer::Timer()
    : m_elapsed(0) {
}

void Timer::tick(double seconds) {
    m_elapsed += seconds;
}

void Timer::reset() {
    m_elapsed = 0;
}

double Timer::lap() {
    double elapsed = m_elapsed;
    reset();
    return elapsed;
}

    Encapsulamiento

    Una clase ofrece una cara pública y mantiene una cara restringida. Quien diseña la clase decide qué partes son accesibles desde fuera (public:) y cuáles quedan reservadas a la propia clase (protected:/private:).

    Por ejemplo, un ascensor puede ofrecernos un botón que pulsar, pero no nos deja manipular el motor y mover la caja directamente:

    /// A simple elevator serving floors from 1 to a fixed top floor.
class Elevator {
public:
    /// Create an elevator serving floors 1 to top_floor.
    /// @param top_floor highest floor served (must be >= 1).
    Elevator(int top_floor);

    /// Request the elevator to go to the given floor. Ignored if
    /// floor is not between 1 and the top floor.
    /// @param floor destination floor.
    void push_button(int floor);

    /// @return the floor where the elevator currently is.
    int get_current_floor() const;

private:
    /// Move the elevator box straight to the given floor, without
    /// any validation. Only push_button() may call this, after
    /// checking that the floor is valid.
    /// @param floor destination floor.
    void move_box(int floor);

    /// Current floor. Starts at the ground floor (1).
    int m_current_floor = 1;

    /// Highest floor served by this elevator.
    int m_top_floor;
};

    Herencia

    La herencia es...

    • reutilización de atributos/métodos en la clase base
    • Constructors aren't inherited automatically — Derived must call each base's constructor explicitly
    • referencias de la clase base para manejo de objetos de las clases derivadas
    • : public A vs : A

    • métodos virtuales y polimorfismo -> actually split polymorphism to its own section

    • access to parent methods A::f() other.Z::g()

    multiple inheritance: - Each base class access specifier (public, protected, private) controls how that base's members are exposed in Derived. - If two bases have members with the same name, you must disambiguate: d.Base1::foo(); in its init list if they need arguments:
