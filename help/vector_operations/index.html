    Operaciones sobre secuencias (WIP REVIEW)¶

    Referencia rápida de las operaciones de IntVectorSkills que iremos completando en Gimnasio vectorial. IntVectorSkills es una caja de herramientas: todos sus métodos son static, se invocan como IntVectorSkills::nombre(...) y ninguno guarda estado propio.

    Las operaciones básicas de IntVectorSkills se agrupan en cuatro familias:

    • Analysis: inspeccionan seq y devuelven un resumen (un bool, un número...).
    • Search: buscan un valor o una posición dentro de seq.
    • Reshape: a partir de una o más secuencias de entrada, devuelven una secuencia nueva (la entrada no cambia).
    • Modify: cambian seq en el sitio (recibida por referencia, no devuelven una copia).

    Además de estas cuatro familias básicas hay una quinta categoría, Complex operations: combinan varias operaciones básicas (a menudo de más de una familia) para resolver un problema mayor. Ya no son métodos de IntVectorSkills, sino funciones independientes que la usan.

    En todos los diagramas, seq a la izquierda es la entrada y el resultado a la derecha es lo que produce (o en qué queda seq, si la operación modifica).

    Estas operaciones cambian seq en el sitio: la reciben por referencia (std::vector<int>&) y no devuelven una copia.

    transform recibe además un objeto que describe qué hacer con cada elemento, ya que todavía no usamos lambdas: una IntOperation (con un método apply).

    Operaciones avanzadas¶

    Estas operaciones ya no son métodos de IntVectorSkills: son funciones que la combinan con otras operaciones básicas (a menudo de varias familias a la vez) para resolver un problema mayor.

    Havel-Hakimi¶

    Determina, mediante el algoritmo greedy de Havel-Hakimi, si degrees es una secuencia gráfica, es decir, si algún grafo simple no dirigido tiene exactamente esos grados de vértice. En cada paso, escoge el vértice con más conexiones pendientes y lo conecta con tantos de los demás vértices con más conexiones pendientes como necesite (los empates se resuelven de izquierda a derecha). Si en algún punto no puede satisfacer las conexiones pendientes de algún vértice, degrees no es gráfica y la función devuelve false. Lo mismo ocurre si degrees está vacío, si no está ordenado de mayor a menor, o si contiene algún elemento cero o negativo.

    /// Determine, via the Havel-Hakimi algorithm, whether some simple
/// undirected graph has vertices with exactly the degrees in
/// `degrees`. At each step, the vertex with the most pending
/// connections is connected to as many of the other vertices with
/// the most pending connections as it needs.
/// @param degrees a candidate graph degree sequence, sorted in
///   descending order: `degrees[i]` is how many other vertices the
///   i-th vertex should connect to.
/// @return true if `degrees` is graphical, i.e. some simple
///   undirected graph has exactly these vertex degrees; false
///   otherwise, including when `degrees` is empty, not sorted in
///   descending order, or contains a zero or negative element.
bool havel_hakimi(const std::vector<int>& degrees);

    Dos ejemplos completos, paso a paso, para comparar un caso gráfico con uno que no lo es.

    Ejemplo gráfico: degrees = [3, 1, 1, 1]¶

    1. Grados restantes: [3, 1, 1, 1]. El vértice con más conexiones pendientes es el 0 (3). Se conecta con los 3 vértices con más conexiones pendientes entre los demás: 1, 2 y 3 (empate a 1 entre los tres, se escogen de izquierda a derecha). Grados restantes tras el paso: [0, 0, 0, 0].
    2. Ningún vértice tiene ya conexiones pendientes: la secuencia es gráfica, havel_hakimi devuelve true.

    Progresión de la lista de grados:

    • [3, 1, 1, 1]
    • [0, 0, 0, 0]

    Ejemplo no gráfico: degrees = [1, 1, 1]¶

    1. Grados restantes: [1, 1, 1]. El vértice con más conexiones pendientes es el 0 (1). Se conecta con el vértice con más conexiones pendientes entre los demás: 1 (empate a 1 con el 2, se escoge el de la izquierda). Grados restantes tras el paso: [0, 0, 1].
    2. El vértice con más conexiones pendientes es ahora el 2 (1). Necesita conectarse con 1 vértice más, pero los dos únicos candidatos que quedan, 0 y 1, ya tienen sus conexiones satisfechas (grado 0). No es posible completar la conexión: la secuencia no es gráfica, havel_hakimi devuelve false.

    Progresión de la lista de grados:

    • [1, 1, 1]
    • [0, 0, 1]

    Havel-Hakimi

    Determina, mediante el algoritmo greedy de Havel-Hakimi, si degrees es una secuencia gráfica, es decir, si algún grafo simple no dirigido tiene exactamente esos grados de vértice. En cada paso, escoge el vértice con más conexiones pendientes y lo conecta con tantos de los demás vértices con más conexiones pendientes como necesite (los empates se resuelven de izquierda a derecha). Si en algún punto no puede satisfacer las conexiones pendientes de algún vértice, degrees no es gráfica y la función devuelve false. Lo mismo ocurre si degrees está vacío, si no está ordenado de mayor a menor, o si contiene algún elemento cero o negativo.

    /// Determine, via the Havel-Hakimi algorithm, whether some simple
/// undirected graph has vertices with exactly the degrees in
/// `degrees`. At each step, the vertex with the most pending
/// connections is connected to as many of the other vertices with
/// the most pending connections as it needs.
/// @param degrees a candidate graph degree sequence, sorted in
///   descending order: `degrees[i]` is how many other vertices the
///   i-th vertex should connect to.
/// @return true if `degrees` is graphical, i.e. some simple
///   undirected graph has exactly these vertex degrees; false
///   otherwise, including when `degrees` is empty, not sorted in
///   descending order, or contains a zero or negative element.
bool havel_hakimi(const std::vector<int>& degrees);

    Dos ejemplos completos, paso a paso, para comparar un caso gráfico con uno que no lo es.

    Ejemplo gráfico: degrees = [3, 1, 1, 1]¶

    1. Grados restantes: [3, 1, 1, 1]. El vértice con más conexiones pendientes es el 0 (3). Se conecta con los 3 vértices con más conexiones pendientes entre los demás: 1, 2 y 3 (empate a 1 entre los tres, se escogen de izquierda a derecha). Grados restantes tras el paso: [0, 0, 0, 0].
    2. Ningún vértice tiene ya conexiones pendientes: la secuencia es gráfica, havel_hakimi devuelve true.

    Progresión de la lista de grados:

    • [3, 1, 1, 1]
    • [0, 0, 0, 0]

    Ejemplo no gráfico: degrees = [1, 1, 1]¶

    1. Grados restantes: [1, 1, 1]. El vértice con más conexiones pendientes es el 0 (1). Se conecta con el vértice con más conexiones pendientes entre los demás: 1 (empate a 1 con el 2, se escoge el de la izquierda). Grados restantes tras el paso: [0, 0, 1].
    2. El vértice con más conexiones pendientes es ahora el 2 (1). Necesita conectarse con 1 vértice más, pero los dos únicos candidatos que quedan, 0 y 1, ya tienen sus conexiones satisfechas (grado 0). No es posible completar la conexión: la secuencia no es gráfica, havel_hakimi devuelve false.

    Progresión de la lista de grados:

    • [1, 1, 1]
    • [0, 0, 1]
